# 운영자 메뉴 설계

- 의도: [`docs/intent/admin-menu.md`](../intent/admin-menu.md)
- 화면 시안: https://claude.ai/artifact/5ut7shZX5n9oWsHJpNo3A2 (화면 5개, 숫자는 모두 예시)
- 상태: **초안. 승인 전에는 구현하지 않는다.**

## 1. 한눈에 보기

서비스 운영자 한 명이 폰에서 모든 가족의 **AI 비용, 학습한 사람, 한도를 다 쓴 사람, 모드별 사용량**을 보고, 사람마다 **하루 한도**를 바꾼다. 보는 것은 숫자뿐이다. 대화, 문장, 리포트 내용은 운영자도 보지 않는다.

## 2. 누가 운영자인가 (중요: 확정 필요)

- 지금 `owner_emails`는 "새 가족을 만들 수 있는 사람"이다. 판매하면 **가족을 만드는 사람마다 이 목록에 들어가므로**, 이 표를 그대로 운영자 기준으로 쓰면 다른 가족의 관리자도 모든 가족을 보게 된다.
- **제안:** 운영자 전용 표 `operator_emails`를 따로 둔다. SQL로 한 줄 넣는다.
  ```sql
  insert into public.operator_emails (email) values ('운영자@gmail.com');
  ```
- `is_operator()` 함수(security definer)가 로그인한 사람의 이메일이 이 표에 있는지 확인한다. 화면 · API · DB 함수 모두 이 함수로 막는다.

## 3. 화면

| # | 화면 | 내용 |
|---|---|---|
| 0 | 내 정보 | 운영자에게만 "운영자 메뉴" 카드가 보인다. 이번 달 비용과 한도를 다 쓴 사람 수를 미리 보여 준다. 아래 메뉴는 그대로 3개다. |
| 1 | 운영자 홈 `/admin` | 맨 위 숫자 4개: ① 이번 달 AI 비용과 2만 원 대비 비율(월말 예상 포함) ② 오늘 · 이번 주 학습한 사람 수 ③ 오늘 한도를 다 쓴 사람 ④ 이번 주 모드별 사용량(오픽 문장 연습 횟수, 끝낸 전화영어 수업 수). 그 아래 가족 목록. |
| 2 | 가족 `/admin/family/[id]` | 가족 합계(이번 달 비용, 오늘 학습 인원, 오늘 사용). 사람마다: 오늘 사용 / 한도 막대, 모드 · 레벨, 연속 학습일 또는 마지막 학습일, 이번 달 비용. "한도 다 씀", "N일째 쉼" 표시. |
| 3 | 사람 `/admin/member/[id]` | 하루 한도 바꾸기(−/+ 5회, 20 · 30 · 50 · 100 빠른 선택, 0~200, 저장하면 바로 적용). 최근 7일 사용 막대(한도를 다 쓴 날은 주황). 이번 달 연속 학습일 · 끝낸 수업 · AI 비용. |
| 4 | AI 비용 `/admin/cost` | 달 선택, 이번 달 합계(원 · 달러 · 호출 수), 하루별 막대, 기능별 비용, 가족별 비용, 모델 이름. |

- "학습한 사람"은 연속 학습일과 같은 기준이다: 그날 전화영어 수업 1회, 또는 오픽 문장 연습 3회 이상.
- 이메일은 사람 화면에서만 앞부분만 보여 준다 (`minjun@…com`).

## 4. AI 비용 기록

- 새 표 `ai_calls`: `id, user_id, family_id, kind, model, input_tokens, output_tokens, cache_read_tokens, cache_write_tokens, cost_usd, created_at`
  - `kind`: `answer`(오픽 답변 만들기), `coach`(코치 한마디), `plan`(수업 계획), `turn`(수업 대화), `hint`, `sos`, `report`
  - `cost_usd`는 **기록할 때** 그 시점의 가격표로 계산해 저장한다. 나중에 가격이 바뀌어도 지난 기록은 그대로다.
- Claude를 부르는 곳(`lib/claude.ts`, `lib/call/claude.ts`)이 응답의 `usage`를 돌려주고, API가 응답한 뒤 `after()`로 기록한다. 기록에 실패해도 학습은 막지 않는다(로그만 남김).
- 가격표 `lib/pricing.ts` (100만 토큰당 달러):

  | 모델 | 입력 | 출력 | 캐시 읽기 | 캐시 쓰기 |
  |---|---|---|---|---|
  | claude-haiku-5-5 | 0.10 | 0.50 | 입력의 0.1배 | 입력의 1.25배 |
  | claude-opus-5-5 | 4.00 | 20.00 | 0.20 | 입력의 1.25배 |

  표에 없는 모델은 Opus 가격으로 계산한다 (비용을 적게 보이지 않도록).
- 환율: 환경 변수 `KRW_PER_USD` (기본 1,400). 화면에는 "추정치"라고 적고, 기록을 시작하기 전의 비용과 실제 청구액은 Anthropic 콘솔에서 확인하라고 안내한다.
- `ai_calls`는 정책 · 권한이 없다. 사용자 화면에서는 읽지도 쓰지도 못하고, 서버의 service_role 연결로만 쓴다.

## 5. 서버 · DB

| 이름 | 하는 일 |
|---|---|
| `operator_emails` 표 | 운영자 이메일. 정책 없음 (SQL로만 넣음) |
| `is_operator()` | 로그인한 사람이 운영자인지 |
| `admin_overview(p_day)` | 홈의 숫자 4개와 가족 목록 |
| `admin_family(p_family)` | 가족 합계와 사람 목록 (숫자만) |
| `admin_member(p_user)` | 사람 상세 (7일 사용, 이번 달 학습 · 비용) |
| `admin_cost(p_month)` | 하루별 · 기능별 · 가족별 비용 |
| `admin_set_limit(p_user, p_limit)` | 하루 한도 변경 (0~200). 바꾼 기록을 `limit_changes`에 남김 |

- 모든 `admin_*` 함수는 security definer이고, 첫 줄에서 `is_operator()`가 아니면 오류를 낸다. **돌려주는 칸은 숫자와 이름 · 레벨뿐**이고, 대화 · 문장 표는 읽지 않는다.
- 화면(`app/admin/*`)도 서버에서 `is_operator()`를 확인하고, 아니면 `/me`로 보낸다. 주소를 알아도 열리지 않는다.
- `limit_changes`: `user_id, old_limit, new_limit, changed_by, changed_at`. 누가 언제 바꿨는지 사람 화면에서 보여 줄 수 있다 (이번 범위에서는 기록만).

## 6. 비용

- 운영자 메뉴 자체는 AI를 부르지 않는다. 추가 비용은 없다.
- `ai_calls`는 호출마다 한 줄이다. 가족 4명 기준으로 월 수천 줄 수준이라 Supabase 무료 플랜 안에 넉넉히 들어간다.

## 7. 하지 않을 것

- 학습 내용(대화, 문장, 리포트) 열람
- 학습 기록 수정 · 삭제, 계정 삭제 · 정지
- 결제, 요금제
- 시간대별 · 화면별 분석, 알림 발송

## 8. 정해야 할 것 (승인 때 함께)

1. **운영자 기준:** `owner_emails`와 별도로 `operator_emails` 표를 새로 둔다 (제안). 그대로 `owner_emails`를 쓰면 가족을 만든 사람 모두가 운영자가 된다.
2. **한도 범위:** 0~200회, 빠른 선택 20 · 30 · 50 · 100
3. **환율:** 1달러 = 1,400원으로 고정하고, 환경 변수로 바꿀 수 있게 한다.
4. **비용 목표선:** 월 2만 원 (홈의 진행 막대 기준)
5. **입구:** "내 정보" 화면의 카드 하나 (아래 메뉴에 탭을 추가하지 않음)
